## Round 9: run Assembly or Fortran interactively in the browser

- **Question:** if the interactive parts are in Assembly or Fortran, how do they run on a static page?
- **Answer:**
  - They use WebAssembly (Wasm, a code format that browsers run). The Actions build compiles the code, and the browser of the visitor runs it.
  - **Fortran:** the Wasm backend of LFortran, LLVM Flang with Emscripten, or f2c with Emscripten for FORTRAN 77.
  - **Assembly:** NASM makes DOS programs that run in js-dos (or v86 for a full PC). Other options: hand-written WebAssembly text, or an assembler and an emulator in the page (RISC-V or 6502).
  - Limits: multithreaded Wasm on GitHub Pages needs the `coi-serviceworker` workaround. Emulators add a few MB.
  - Claude Code suggested two proof-of-concept demos. The first is a Fortran heat-equation kernel with a slider and a chart. The second is a NASM Mode 13h program in js-dos.

- **The first test:** a new folder `game/`.
  - The B side (`lab/sine_table.f90`) makes 256 sine values as whole numbers.
  - The A side (`src/spike.asm`) draws the curve and moves a yellow dot along it. It is 655 bytes, with 8086 instructions only (`cpu 8086`).

- **Build:** this computer has no Fortran compiler, no assembler and no DOSBox, and installation needs a password. Thus, `game/dev.sh` runs `game/build.sh` in an Ubuntu 24.04 container (Docker). GitHub Actions runs the same script on Ubuntu 24.04. If the check fails, nothing is published.
